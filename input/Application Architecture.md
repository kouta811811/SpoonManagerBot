## 2. 設計方針サマリ
イベント駆動型 Python 3.12 によるステートレスな処理方式を採用する。  
受信したWebhookリクエストに対してHMAC-SHA256署名検証を先行実施し、不正なアクセスを遮断した上で、イベント種別（入室/コメント/ギフト/配信終了）に応じて専用ハンドラーへ振り分ける。DynamoDBを用いて重複イベントの破棄（冪等性制御）と配信セッション管理を行い、外部API呼び出し時は5秒間のクールダウンおよび指数バックオフリトライを適用して規約に適合した安定運用を行う。

## 3. 全体処理フロー

```
[Webhook受信]
       │
       ▼
[署名検証 (auth.py)] ──── 失敗 ────► HTTP 401返却 (即時切断・警告ログ)
       │ 成功
       ▼
[冪等性判定 (dynamo_service.py)] ── 重複 ──► HTTP 200返却 (スキップ)
       │ 新規イベント
       ▼
[ディスパッチャー (dispatcher.py)]
       ├── 入室イベント   ──► [ウェルカムメッセージ生成]
       ├── コメントイベント ──► [コマンドパース・権限判定]
       ├── ギフトイベント   ──► [お礼メッセージ・集計]
       └── 配信終了イベント ──► [セッションクローズ・TTL設定]
       │
       ▼
[外部API送信制御 (api_client.py)]
       ├── クールダウンチェック (同一コマンド5秒間隔)
       ├── 指数バックオフ (HTTP 429 発生時)
       └── 送信実行
       │
       ▼
[HTTP 200 OK 返却]
```

## 4. モジュール別仕様

### 4.1. Webhook受信・署名検証モジュール (`auth.py`)
- **ヘッダー抽出**: HTTPリクエストヘッダーからプラットフォーム署名（`X-Signature` 等）を取得。
- **シークレット取得**: SSMパラメータストア（`SecureString`）から共有シークレットを取得。Lambda実行環境のメモリにキャッシュし、コールドスタート時以外はSSMへのアクセスを最小化。
- **HMAC計算**: 受信した生のリクエストボディ文字列（UTF-8）とシークレットを用いて HMAC-SHA256 ダイジェストを計算。
- **照合**: `hmac.compare_digest()` を用いてタイミング攻撃を防止しながら照合。
- **検証失敗時**: 詳細なエラー理由をクライアントへ返さず、即座に `HTTP 401 Unauthorized` を返却。

### 4.2. イベントディスパッチャー (`dispatcher.py`)
- ペイロード内の `event_type` を解析し、登録されたハンドラーにディスパッチする。
  - `live.join`: 入室ハンドラー（`join_handler.py`）
  - `live.comment`: コメントハンドラー（`comment_handler.py`）
  - `live.gift`: ギフトハンドラー（`gift_handler.py`）
  - `live.end`: 配信終了ハンドラー（`end_handler.py`）

### 4.3. コマンドパーサー & 業務ロジック (`comment_handler.py`)
- **プレフィックス判定**: コメントが `!` または `/` で開始されているか判定。
- **構文解析**: コマンド部と引数部に分割（例: `!song リクエスト曲名` $\rightarrow$ コマンド: `!song`, 引数: `リクエスト曲名`）。
- **権限レベル（ロール）判定**:
  1. `HOST`（配信者本人）: 全コマンド実行可能（配信設定変更、Bot停止等）
  2. `MANAGER`（固定マネージャー）: 運営管理コマンド実行可能（曲順整理、アナウンス固定等）
  3. `LISTENER`（一般リスナー）: 照会系コマンドのみ許可（`!help`, `!song`, `!dice` 等）

### 4.4. 状態管理・データベースI/O方式 (`dynamo_service.py`)
- **テーブル名**: `LiveSessionState`
- **キー設計**:
  - Partition Key (PK): `SESSION#{LiveSessionId}`
  - Sort Key (SK): `EVENT#{EventId}`
- **二重実行防止（冪等性）**:
  - `attribute_not_exists(PK)` 条件付き書き込みを実施。同一 `EventId` が既に存在する場合は例外をキャッチして処理をスキップし、`HTTP 200 OK` を返却。
- **データ破棄（TTL）ポリシー**:
  - レコード書き込み時に `ttl_timestamp`（現在時刻 + 24時間 のUNIXエポック秒）を付与。DynamoDBの標準機能により自動消去。

### 4.5. 外部API連携 & レートリミット制御 (`api_client.py`)
- **HTTPクライアント設定**: タイムアウト 3秒。
- **同一コマンドクールダウン**: DynamoDBまたはメモリキャッシュを参照し、同一コマンドの連続実行には最低5秒のインターバルを強制。
- **指数バックオフリトライ**:
  - 外部APIから `HTTP 429 Too Many Requests` を受信した場合、`Backoff = min(Base * 2^retry, Max)`（初期待機 0.5秒、最大2回リトライ）を適用。
  - リトライ上限を超過した場合は処理を諦め、Webhookとしては `HTTP 200 OK` を返却してエラーログに記録（Webhookの再送ループ防止）。

## 5. 運用ログ設計 (`logger.py`)
- **出力形式**: CloudWatch Logs 向けの構造化 JSON ログ。
- **出力レベル**:
  - `INFO`: Webhook受信（イベントID、種別）、コマンド実行結果、API送信成否
  - `WARN`: 署名検証失敗、レート制限到達、クールダウン中のコマンド破棄
  - `ERROR`: 予期せぬ例外、外部API通信タイムアウト
- **マスキング規程（PII除外）**:
  - APIトークン、共有シークレット、チャットコメント全文を生ログに出力しない（必要な場合はハッシュ値または長さを記録）。
